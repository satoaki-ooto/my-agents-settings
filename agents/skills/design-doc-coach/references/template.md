# Design Doc Template

この雛形に従って Design Doc を出力する。セクションの取捨は内容次第。ただし「変更の地図」「重要な設計判断とトレードオフ」「変更の段階」は削らない。

```markdown
# (タイトル)

# 背景
<!-- 前提やこの実装を行う動機を記載する -->

# 目的 = このプロジェクトのゴール
<!-- プロジェクトの目的を端的に1-2行で -->

# ゴールインパクト
<!-- 達成時のインパクト、可能なら定量的に -->

# やること
<!-- このスコープ内で技術的にやることを箇条書きで列挙 -->

# やらないこと
<!-- やることの対比で、スコープ外のものを箇条書きで列挙 -->

# 概要
<!-- 概要設計・やることをどう実現するか -->

## 変更の地図
<!-- 3つの視点から必要なものを図で示す。画像 + 再現用ソースの形式(下記「図の規約」参照) -->

### 境界と差分(静的) [必須]
### データの流れ(動的) [必要に応じて]
### 状態・完了(振る舞い) [必要に応じて]

# 詳細設計

## 重要な設計判断とトレードオフ
<!-- 壁打ちで決まったことを記録。agent の発明ではなく人の回答を載せる -->

| 検討した論点 | 決定事項 | 考慮したシナリオ(なぜ避けたか / 許容したか) | 見直しの条件 |
| :--- | :--- | :--- | :--- |
|  |  |  |  |

## 変更の段階
<!-- 実装タスク一覧ではなく、独立して検証できる成果の単位。
     ファイル・関数単位ではなく「設定の契約を定める」「共有境界を整える」等の粒度 -->
- Phase 1:
- Phase 2:
```
